源码中能核对的 HD 改动

对照对象：当前被包导入的模块，以及仓库内留存的 *_1.py / 包内官方风格 YAML。下面只描述张量路径与配置字面量，不推断「更好」或「更准」。

1. Proto：三次 ×2 上采样

ultralytics/nn/modules/head.py 的 Segment 用 P3 特征调用 self.proto(x[0])。当前 Proto（block.py）为：

cv1 → ConvTranspose2d(×2)
cv2 → ConvTranspose2d(×2)
cv3 → ConvTranspose2d(×2)
cv4 → 输出通道 c2（掩码原型数）

同文件里被注释掉的旧 Proto，以及 block_1.py 中仍生效的实现，是一次 ConvTranspose2d(×2) 后接两层卷积。P3 相对输入步幅为 8：一次 ×2 得到约 1/4 图；三次 ×2 得到约 1/1 图。这就是本 fork 名称里「HD」在结构上的对应点。

2. 训练掩码不下采样

ultralytics/cfg/default.yaml 写明 mask_ratio: 1。同仓库 default_1.yaml 仍为 mask_ratio: 4。数据管线 Format(..., mask_ratio=hyp.mask_ratio) 会按该比值缩小多边形栅格。比值为 1 表示训练用掩码按配置保持与图像同分辨率（仍受 imgsz 等上游几何变换约束）。

3. 根目录分割 YAML 的 Segment 参数

YAML 字面量对照（不是性能表）
文件 最后一层 按 Segment(nc, nm, npr) 阅读
yolov8-seg.yaml（仓库根） Segment, [nc, 4, 32]，nc: 13 掩码系数通道 nm=4，原型通道 npr=32
ultralytics/cfg/models/v8/yolov8-seg.yaml Segment, [nc, 32, 256]，nc: 11 常见上游取值 nm=32，npr=256

train.py 调用的是 ./yolov8n-seg.yaml（带尺度后缀的写法）。根目录实际文件名是 yolov8-seg.yaml。本页不假设训练入口在未改路径时一定能找到模型文件。

4. 推理侧已打开的上游开关

default.yaml 中 retina_masks: True。这是 Ultralytics 已有选项，用于按更高分辨率恢复掩码，不是本仓库独有算子。本页没有延迟或显存测量。

明确不是评测结论的部分

  • head.py 里有注释掉的导出/部署 forward，并指向外部 ncnn-android 项目。注释代码不能当作已验证的移动端实现。
  • block.py 的 Proto 与 ProtoBack 结构相同；Segment 只实例化 Proto。
  • 更高分辨率掩码会增加计算量，但仓库没有给出 FPS、mAP 或边缘质量数字。
