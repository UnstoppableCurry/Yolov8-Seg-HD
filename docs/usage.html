用法与数据约定

README 声称调用方式与当时 Ultralytics 对齐（from ultralytics import YOLO 一类 API）。仓库没有独立的安装文档或 pyproject.toml / setup.py。以下只整理仓库里写明的目录和脚本。

README 中的数据目录

train/
  images/   1.jpg, 2.jpg
  labels/   1.txt, 2.txt
  label/    1.png, 2.png
val/
  images/
  labels/
  label/
  • README：label 中的 PNG 必须与 labels 中的 TXT 对应。
  • README：TXT 轮廓「其实就是二值图上绘制的白色区域」。
源码与 README 并不完全对齐 ultralytics/data/dataset.py 仍走 YOLO 多边形 TXT 缓存；构造标签时 mask=None。把 PNG 路径写成 labels → label、txt → png 的那一行是注释掉的。因此：README 描述了 PNG 约定，当前扫描逻辑不能被说成「已经读取 PNG 监督」。

仓库里的训练入口

train.py 字面内容（路径已是作者机器上的绝对路径，不能直接在其他环境运行）：

  • 设置 matplotlib 后端为 TkAgg。
  • YOLO('./yolov8n-seg.yaml').load(<本机 best.pt>)。
  • model.train(data='./coco128-seg-seal.yaml', epochs=200, imgsz=640, resume=True)。

coco128-seg-seal.yaml 的 path 同样是本机目录；train/val 相对路径为 train/images、val/images。类别名写在该 YAML 的 names 里（印章相关中文名，13 类，与根目录 yolov8-seg.yaml 的 nc: 13 一致）。YAML 头部仍留有 Ultralytics COCO128-seg 说明注释，但实际 path 已改成本机数据，本仓库不包含这些图像。

调用形态（与上游同年份文档同类）

在已安装本仓库 ultralytics 包的前提下，上游式用法在源码中仍然存在，例如构造 YOLO 后 train。具体依赖、CUDA、以及官方后来增加的可视化 / OBB 等，README 已声明不支持或不等价于「最新 Ultralytics」。本页不提供未在仓库出现的命令行教程，以免编造可运行步骤。
