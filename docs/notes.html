仓库结构与限制

顶层与主要包

Yolov8-Seg-HD/
  README.md                 作者短说明与数据目录示意
  train.py                  本机路径的训练示例
  coco128-seg-seal.yaml     本机 path + names
  yolov8-seg.yaml           根目录分割结构（Segment [nc, 4, 32]）
  yolov8n.pt                仓库内权重文件（检测命名）
  ultralytics/              8.0.170 风格的包，含分割改动
    nn/modules/block.py     当前 Proto（三次上采样）
    nn/modules/head.py      Segment 调用 Proto
    cfg/default.yaml        mask_ratio: 1 等
    data/dataset.py         TXT 缓存；PNG 路径行被注释
    yolo/                   仅有子包占位，不是完整旧引擎
  docs/                     本静态站（GitHub Pages 只发布此目录）

包内还有大量 *_1.py / *_1.yaml。它们未被 ultralytics/nn/modules/__init__.py 等入口导入。阅读改动时以不带 _1 的文件为准；_1 仅适合当对照副本。

ultralytics/cfg/models/ 仍带有检测、分割、P6 等 YAML，以及 tracker 配置。这是上游包布局的残留，不表示本说明页覆盖那些任务的评测。

限制（均能在仓库内核对）

  • 没有本项目结果图。 说明页里的巴士图是 Ultralytics 上游样例。
  • 没有可引用的指标。 未发现 val 日志、论文表或公开排行榜记录。
  • 数据不在仓库中。 配置指向 E:\... 一类路径。
  • 训练脚本不可移植。 train.py 依赖本机权重、TkAgg 与 yolov8n-seg.yaml 文件名。
  • README 的 PNG 约定与当前 Dataset 实现不一致（见 用法）。
  • 与「最新 Ultralytics」不等价。 README 已写明可视化、旋转等后续特性不支持。
  • 移动端实时性未验证。 仅有作者目标与注释掉的导出函数。
  • 工程完整度。 无根 LICENSE 文件、无依赖锁文件、无测试套件覆盖训练；ultralytics/yolo 基本是空壳。
  • 权重文件。 Pages 工作流只上传 docs/，不会发布 yolov8n.pt 或 Python 源码。

本静态站

文件在 docs/。官方 GitHub Actions 工作流把该目录部署到 https://unstoppablecurry.github.io/Yolov8-Seg-HD/。站点无表单、无第三方脚本、无跟踪。
